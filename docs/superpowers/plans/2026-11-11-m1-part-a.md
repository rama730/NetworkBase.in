# M1 — Part A: one-click agent sign-in, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native) to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an agent is approved with one click (Full help · All my workspaces · 30 days by default), every request is still checked against the workspace it touches, the terminal and the agent both read the same access sentence, and an agent can ask for more access.

**Architecture:** "All my workspaces" is an agent session with `workspace_id = NULL`. The pause, organization and workspace checks move from sign-in time to each request: path and query routes in `bearerPrincipal`, body and task routes in `denyOutsideTokenWorkspace`. Presets and the sentence live in one module, `src/lib/agents/access.ts`, which the page, Settings, `/api/v1/me`, the MCP card and the CLI all use. The CLI prints the server's sentence; it never writes its own.

**Tech stack:** Next.js 16 route handlers and server actions, Drizzle with Postgres migrations, zod 4, the CLI (Node 20+, no dependencies), node:test, and Playwright browser fixtures.

**Spec:** `docs/superpowers/plans/2026-11-11-cli-agents-next-round.md`: Part A (A1–A10, A9b), Part 0.8 items #2, #3, #12 and #16, and F7. Ledger: rows with `milestone: "M1"` in `docs/superpowers/plans/2026-11-11-ledger.json`. Every task below names the ledger sections it closes.

## Global constraints

- **Presets:**
  - **Full:** `AGENT_BASE_SCOPES` plus `task:complete`, `file:final` and `doc:write`.
  - **Small:** `AGENT_BASE_SCOPES` only.
  - **Read:** `workspace:read`, `task:read` and `file:read`, stored explicitly.
  - **Custom:** base plus the ticked extras.
- **Existing tokens:** an empty stored scope list keeps meaning "base", and existing bound agent tokens behave exactly as today.
- **Expiry:** 7, 30 or 90 days (`AGENT_EXPIRY_DAYS`); default 30.
- **Default pre-fill order:** what the CLI asked for → the remembered choice for this agent name → Full · All · 30.
- **"Verify it's you"** reuses the existing 5-minute window (`SECURITY_STEP_UP_MAX_AGE_SECONDS`).
- **Asking for more:**
  - at most 3 open requests per session, each expiring in 24 hours
  - "No" blocks the same scope for 24 hours
  - "Once" covers the next request with the same method and path within 1 hour
- **New error codes:** `ACCESS_REQUESTED` (403), `ACCESS_DENIED_BY_PERSON` (403), added to `src/lib/api/errors.ts` with docs anchors.
- **Part 0.2–0.5 checklists apply to every route, command and screen.** Migrations are 0082–0084, in this order.

## Review focus

1. **Existing bound agent tokens and personal access tokens behave exactly as before:** same scopes, same refusals (Task 3 test "bound tokens unchanged").
2. **An all-workspaces agent calling a route without an `agent` mode** is refused, never let through (Task 3).
3. **Pausing a workspace or an organization turning agents off after approval** refuses the next request in that workspace only (Task 3).
4. **A code that expires between page load and Approve** shows "expired, run again", not a crash (Task 7 fixture row).
5. **"Verify it's you" expiring while changing access** asks again and keeps the chosen settings (Task 6).
