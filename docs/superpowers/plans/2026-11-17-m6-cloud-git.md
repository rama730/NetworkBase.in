# M6 (Part G cloud and git, F4) phase plan

> Native execution, test-first. Ledger: milestone M6 (25 rows: G14, G18, G10/G19/G24/G24b/G26 rows for G-4 and G-5, F4 x3).

**Goal:**
- Cloud agents can work on a draft without a computer: list, read, search and edit files in a change set (routes 14–18, `fs_*` tools), with a text index for search.
- Git users turn commits into a change set (`--from-git`), and an applied change set can go to a GitHub-synced repository as one commit.
- The F4 agent controls: `nb agent activity`, `nb agent pause` and `resume`, and OAuth refresh tokens for hosted MCP.

## Decisions (recorded here, as the report asks for changes to its design)

1. **The text index fills on read, not from a background job.**
   - **Report (G14):** "filled after every version write by a background job, with a one-time backfill".
   - **Built:** a search first indexes the workspace's text files that have no entry yet (up to 300 a search, 8 at a time), then searches.
   - **Why:** no Inngest run per save, so the free-plan limit isn't touched (G19, G26), and nothing to backfill; a workspace nobody searches costs nothing.
   - **Ceiling:** the first search in a big workspace is slower; a later search finishes what's left.
   - **Kept in step:** content is keyed by hash, so it can't go stale. The daily retention job removes entries no live file or open change set refers to.
   - **No path table:** paths come from the workspace's files, so `file_text_index_paths` isn't needed.
2. **The GitHub push stays a reviewed sync.**
   - **Report (G18):** a background job pushes one commit after apply.
   - **Built:** in a GitHub-synced workspace, an applied change set shows "Not pushed to GitHub yet". Push opens the existing Repository sync review with the commit message filled in: the title, the message and `NetworkBase-Task: #N` (or `NetworkBase-Change-Set: <id>` when the set isn't on a task).
   - **Why:** pushing needs the person's GitHub sign-in and the sync's own review (workflow-file checks, conflicts with the repository); a silent push would bypass both.
3. **Migrations:** 0094 (`file_text_index`, plus an index on `change_set_items.content_hash` for the clean-up) and 0095 (`oauth_refresh_tokens`, report F4's table, numbered after M5 took 0091–0093).
4. **Refresh tokens:** a sign-in the person approved for 7 days gets none (they chose a short one). Renewed access tokens last 30 days; refresh tokens 90, bound to the client.
5. **`nb agent activity`** reads the 24-hour undo log (`undo_operations`) of the person's agents, so Undo per session is the existing undo.

## Tasks

1. **0094 `file_text_index`:** `content_hash` PK, `content`, `bytes`, `indexed_at`; GIN `gin_trgm_ops` on content; RLS, `nb_app`.
   - Domain `src/lib/domain/change-set-fs.ts`:
     - `listFiles` (glob, draft view)
     - `readFiles` (up to 50, 1 MB each inline)
     - `searchFiles` (trigram narrowing, exact lines in code, regex with a time limit, up to 200 matches; task-private files excluded as the manifest excludes them)
     - `editFile` (`EDIT_NOT_FOUND`, `EDIT_NOT_UNIQUE` with the count)
     - `writeFile`, `deleteFile`, `moveFile`
   - Tests: `tests/db/change-set-fs.test.ts`.
2. **Routes 14–18.**
   - `/workspaces/:id/fs/list|read|search`
   - `/change-sets/:cs/fs/edit|write|delete|move`
   - Token rules (read: `file:read`; writes: `file:write`) and the `/projects` aliases.
3. **CLI and agent tools.**
   - Hidden `nb fs list|read|search|edit|write|delete|move` back the `fs_*` tools.
   - A write without a change set opens one for the agent's sign-in ("Changes by …").
   - Hosted MCP gets the tools; local agents keep their own file tools.
   - Tests: `packages/nb-cli/test/fs.test.mjs`.
4. **`nb change finish --from-git <range>`:** the files the commits changed (as at the range's end), the subjects as title and message. Test against a temporary git repository.
5. **The GitHub push link** in the Changes view for synced workspaces, prefilling the Repository sync review. Browser test.
6. **F4.**
   - `nb agent activity`: agent changes grouped by session, with Undo per session.
   - `nb agent pause` and `resume`: owner only, the settings switch.
   - OAuth `refresh_token`: rotated on each use; the old one is refused and revokes the chain if it's reused; 90-day life.
   - Tests on all three.
