# M2 (Part B: labelling agent work) Implementation Plan

> Native execution, test-first. Ledger rows: milestone M2 in `2026-11-11-ledger.json` (17 rows, all section B).

**Goal:** the person is always the author, shown as "Ram · with Claude Code"; workspace owners choose who sees that (Everyone, Only the person, No one); organizations keep it visible to staff where the class asks; the record (`via`, `agent_name`) never changes.

**Architecture:** one pure rule `visibleVia(viewer, scope, row)` plus a loader `labelScope(viewerId, workspaceId, taskId?)` in `src/lib/agents/via-visibility.ts`, applied in every server read path that sends a label. The browser can no longer read `via`/`agent_name` at all (column grants), so "No one" also means the data never reaches other people.

**Spec:** report Part B.

## Findings that shape the build (2026-11-11)
- Browser roles have table-level SELECT on `tasks`, `task_subtasks`, `task_comments`, which includes `via` and `agent_name`; the task panel reads subtasks (with those columns) straight from Supabase. Fix: column grants like `workspaces` already has (every column but the two), and subtask labels come from a server action.
- Subtasks store no author, so "Only the person" can't be decided for them. Migration adds `task_subtasks.created_by`; older agent-made subtasks have none and stay hidden under "Only the person".
- Emails show no label today; the CLI shows labels only in `nb watch` (`/api/v1/events`). Exports (F8) and Part H don't exist yet: they must use the helper when built (guard test).
- Read paths that send a label: file versions (`listFileVersionsPage`), task comments (`readDiscussionRows` and the single-comment read), subtasks (new action), workspace activity (action and API route), events route. Hand-ins and the review queue stay as they are (spec).

2. **The rule** (`src/lib/agents/via-visibility.ts`): `visibleVia(viewer: { id, staff }, scope: { setting, orgForced }, row: { via, agentName, authorId })`. Hidden when `via` is null; org-forced + staff viewer → shown; `everyone` → shown; `person` → only `authorId === viewer.id`; `none` → hidden for all. `labelScope(viewerId, workspaceId, taskId?)` loads the setting, whether the workspace is an organization or under one, the effective AI policy (the assignment copy's when `taskId` is a copy, else the organization default), and whether the viewer is owner/admin or an organization teacher/reviewer. Tests: `tests/unit/via-visibility.test.ts` (setting × viewer matrix, org forced), `tests/db/via-visibility.test.ts` (loader, assignment copy can't hide). Rows B.c511220f, B.a67715a5, B.176e23b6, B.f3c04d1d.
