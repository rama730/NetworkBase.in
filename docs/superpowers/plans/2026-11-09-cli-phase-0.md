# CLI Phase 0 — Safety Net Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give `packages/nb-cli` a test harness, type checking, lint guard, CI workflow and recorded baselines, with no user-visible change.

**Architecture:** Zero-dependency `node:test` suites under `packages/nb-cli/test/`, driven by a local `node:http` fake of the NetworkBase API. The 1.x CLI (`bin/nb.mjs`) is exercised as a black box (spawned with a temp `HOME` and `NETWORKBASE_TOKEN`), so the same harness keeps working when Phase 2 replaces the internals.

**Tech Stack:** Node 22 (`node:test`, `node:http`, `node:child_process`), TypeScript `--checkJs` from the repo, ESLint flat config, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-09-cli-and-agents-report.md` (A13.1–A13.4, A13.8, §40), master plan `~/.claude/plans/now-whatever-is-in-sorted-badger.md` (P0.1–P0.3).

## Global Constraints

- No runtime dependencies in `packages/nb-cli` (A3.15); dev tooling comes from the repo root.
- Tests never touch the real `~/.networkbase` or the network: every spawn gets a temp `HOME` and a fake API URL.
- Stage named files only; commit locally; no push.
- Budgets (A13.8) are recorded in Phase 0 and enforced from Phase 2: package < 150 KB unpacked, `nb --version` < 120 ms, `nb help` < 200 ms (median of 10, Linux runner).

## Review Focus

- A test that forgets to isolate `HOME` would read or delete the developer's real credentials → `runCli` always creates a temp `HOME`; test asserts the real file is untouched.
- Fake server port collisions in parallel test files → listen on port 0.
- `script` differs between macOS and Linux → `runTty` picks the syntax per platform and skips on Windows.
- Known 1.x bugs must not turn CI red in Phase 0 → they are `{ todo: true }` tests naming the finding (F5), so they flip to real tests in Phase 2/3.
- Benchmarks against the fake server measure client overhead only → the notes say so next to the numbers.

State lives in `server.state` (`files`, `tasks`).
- `runCli(args, { api, token?, cwd?, env?, input?, timeoutMs? }) → Promise<{ code, stdout, stderr, home, cwd }>`; creates temp `HOME` and `cwd` when not given.

- [ ] Tests in `smoke.test.mjs`: `--version` prints the package.json version and exits 0; `whoami --json` against the fake returns `authenticated: true`; a 503 on `session` makes `whoami --json` report `authenticated: false` without crashing; `runCli` never writes to the real `~/.networkbase` (mtime unchanged).
