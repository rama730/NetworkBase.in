# M4 (Parts C and D) phase plan

> Native execution, test-first. Ledger: milestone M4 (168 rows: C, C1–C16, C14b, C15, D, D22b, D23, D24, 0.8 #6/#13–#15, F7 `nb upgrade` and "what's new", E2 single-file install).

**Goal:** the CLI for a person at the terminal (Part C) and for an AI using it (Part D), plus the 12 walkthrough findings (C16, D24).

**Why phases:** M4 is too big for one deploy. Each phase is built, tested, reviewed, deployed with its own go-ahead, and checked live. CLI versions follow the order releases ship (register R2): 2.1.0, 2.1.1, 2.1.2, 2.1.3.

## Phases

### M4a: the everyday terminal (CLI 2.1.0, no migration)
The C14b MVP plus every walkthrough finding.
- **C16 (all 10):**
  - push links to the started task
  - an oversized named file is an error
  - create and start assign you
  - "#1" instead of "-1"
  - a one-line status after linking
  - plain undo wording
  - a `whoami` sentence
  - the next step after create
  - a faster start
  - `nb class` aliases
- **C1:** the home screen (bare `nb` knows signed out, unlinked or linked), advice in the right order, `nb init` suggestions, aliases, a shorter help, "did you mean" for flags.
- **C2 MVP:**
  - `task create --due --to --sprint`
  - `task list` filters and sort
  - `nb next`
  - tasks by words, natural dates
  - quick capture `nb task add`
  - bulk move, assign and edit (one transaction, one undo)
- **C3 MVP:** `file history` shows "based on" and the active version; `nb file use`.
- **C4 MVP:** `nb inbox reply`, `nb inbox approve`.
- **C5:** every error ends with its next command (audit test) and its docs link.
- **C6:** `nb queue`, `retry` and `drop`; the expiry warning and renewing the same sign-in.
- **C8:** the current task (`nb done`, `nb comment` on it, `nb task stop`), `nb prompt`.
- **D24:** signed local yes tokens; counts name their workspaces.
- **Server:**
  - `GET /api/v1/home`
  - `GET /api/v1/resolve`
  - `POST /api/v1/tasks/bulk` (undo kind `tasks.bulk`)
  - the create route takes due, assignee and sprint
  - list filters
  - `renewSessionId` on device login

### M4b: working together and files (CLI 2.1.1, migrations 0087, 0088)
- **C2 rest:** labels, blocked by, watch, star tasks, reminders (Inngest), `--format` on lists.
- **C3 rest:** trash and restore, mkdir and copy, starred and recent files (stars move to the server, and the Files tab reads them), locks, remembered partial pulls, upload progress and resume, `--dry-run` everywhere, a diff between versions.
- **C4 rest:**
  - inbox settings
  - @mentions
  - comment reply, edit, delete, and docs

  - `nb review` diff and batch
- **C5 rest:** `nb help <topic>`, `nb upgrade`, F7's "what's new".
- **C6 rest:**
  - the network-drop CI test
  - the app plus `nb watch` conflict test
  - the 5,000-file timing test
  - proxy and certificate settings
  - the startup budget for `status`
- **C10–C14:** `nb edit`, `open --code`, `undo --list`, `--format`, relative times, links everywhere, the one-screen task view, `nb commit`, pull request links (the server half), `nb watch --inbox`, `nb uninstall`.
- **Search** across tasks, comments, docs and people.

## Method per phase
1. A short task list with ledger keys, written as the phase starts.
2. Test first: CLI fake-server tests, DB tests for every route, schema export, the help snapshot and `commands.json`.
3. Gates:
   - unit, DB and CLI suites
   - CLI budgets
   - typecheck and lint
   - SQL governance
   - plan ledger
   - the agent test for M4c
4. Review: ponytail-review, then a correctness pass.
5. Go-ahead, then migrations, push, the CLI tag, the user's npm approval, and a live check (the terminal journey from E1 and the member and owner steps where needed).
