## What M7 builds

**F1. Classes:**
- **Students:**
  - `nb assignment list --due today|week|overdue|<date>` across all classes.
  - `nb next` also lists the nearest assignment due.
  - The route is `GET /api/v1/assignments?due=…`.
- **Teachers:** `nb class progress <assignment>`, showing every student as handed in, late, returned, approved or missing.
  - The route is `GET /api/v1/assignments/:master/progress`, over the existing roster and hand-in data. It's for teachers and the organization's admins.
- **Announcements:** `nb class announcements [org]` reads the organization's announcements, and new ones also show in `nb inbox` (they already arrive as notifications).
  - The route is a read over `org-updates` announcements.

**F2. Sprints:**
- **Create:** `nb sprint create "<name>" --from monday --to friday`
- **Add tasks:** `nb sprint add <sprint> 3 4 5`
- **Close:** `nb sprint close <sprint>`, which moves the unfinished tasks to the next sprint, or back to the backlog if there is none.
- **Burndown:** `nb sprint view` gets a text burndown (tasks left per day).
- **Wording:** the commands use the organization's own words (Unit, Week) in what they print.
- **Routes:** `POST /workspaces/:id/sprints`, `POST …/sprints/:s/tasks` and `POST …/sprints/:s/close`, over the existing sprint server functions.

**F3. Workspace admin (owners and admins):**
- **Workspaces:** `nb workspace create "<title>"`, `nb workspace settings [--set key=value]` and `nb workspace archive`.
  - These are v1 routes over the existing workspace actions.
  - Archive asks for a yes, and needs "Verify it's you" (F5).
- **Agent policy:** `nb agent policy ask-all|important|trust-docs`. `PATCH /workspaces/:id/agents` takes `{ policy }` next to the existing `{ paused }`.
- **Docs:** `nb doc add <file>` and `nb doc remove <slug>` (the file stays), over the existing link and unlink actions.

**F5. Account and security:**
- **Country:** `nb token list` shows each token's last country (0076). When a token is used from a new country, a security notification goes out.
- **`nb whoami --security`:** your sign-ins, two-factor on or off, and the last 10 security events. The route is `GET /api/v1/me/security`.
- **"Verify it's you" in the terminal** for risky actions (making a personal access token, removing a member, archiving, exporting):
  - The CLI opens a short browser page, as `nb agent access` does (A10).
  - The person verifies there, and the command continues.

**F6. Automation:**
- **`nb api <METHOD> <path> [--data json]`:** calls any `/api/v1` route with your sign-in. It goes through the same token route list and scopes, so nothing new becomes reachable. Writes ask for a yes unless you pass `--yes`.
- **The GitHub Action `networkbase/action`:** push build output to a task, or move a task when a pull request merges, using a workspace token.
  - **User step:** create the public repository `networkbase/action`. The action's code, tests and a test run follow.
- **Recipes in `/docs/cli`:** start the day, hand in an assignment, review a class, set up an agent, back up a workspace, cron and CI. CI runs each one against the fake server.

**F8. Data and privacy:**
- **`nb export [--branch x | --all-branches]`:** a zip of the workspace's files (the live zip download) plus `export.json` holding its tasks, comments and docs.
  - Agents need a yes, and people need "Verify it's you".
  - The route is `GET /workspaces/:id/export`, streaming. With Part H, a branch's files come from its tree.
- **`nb logout --purge`:** removes everything the CLI keeps (credentials, caches, the queue, base copies). `/docs/cli` gets a section on what is kept, and where.

**F9. Accessibility:**
- **Never colour alone:** a unit test runs every printer with colour off and checks each state still has a word or symbol.
- **`--plain` with a real screen reader** (VoiceOver, Narrator) is a **user step**, as a short checklist I write. Automation can't stand in for a person listening.

**F7. The npm `next` tag:** it moves from 2.0.4 to the current release. **User step:** `npm dist-tag add @networkbase/cli@2.5.0 next`, which needs your npm two-factor code. Publishing stays trusted-only.

## Decisions

1. **Several small commands, one release:** site routes first, then CLI 2.5.0. The size budget (800 KiB) holds; the commands load only when used.
2. **"Verify it's you" in the terminal uses the browser** (decision F5). No password or code is ever typed into the CLI.
3. **Export is files plus `export.json`, not a database dump.** Messages and chats stay out, because they're people's private conversations.
4. **Sprint close** moves the unfinished tasks to the next planned sprint, the one starting soonest after this one ends. With none, they go back to the backlog. It says which.

## Risks

- **Export size:** it reuses the streaming zip that's already live, with the same limits (20,000 files) and `--branch` for one branch.
- **Terminal step-up:** a stolen token still can't pass it, because the browser page needs a signed-in session and a recent verification.
- **The new-country warning** can be noisy when travelling: one notification per token per country.
- **Sprint close on a large sprint:** it runs in one transaction, capped at 500 tasks, with a clear error beyond that.
