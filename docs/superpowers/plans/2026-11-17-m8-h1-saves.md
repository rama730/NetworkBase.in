# M8 phase H-1 (saves on main) plan

> Native execution, test-first. Report Part H (H3, H10–H12, H16, H18, H19 H-1 rows). Each phase deploys on its own with the user's go-ahead.

**Goal:** with the workspace's "Branches" setting on, every change to main's files becomes a save. People see workspace history and one save's page (files, diffs, browse files at that save, download as zip), and can revert a save, from the app and from `nb log`, `nb show` and `nb revert`.

## Decisions (differences from the report's design)

1. **Saves are recorded by the database, not by a `recordSave` call in every writer.**
   - **Report (H12):** each writer calls `recordSave(tx, …)`, and a unit test fails when a writer doesn't.
   - **Built:** statement triggers on `workspace_nodes` (insert, update, delete) add the changed files to the transaction's save. A deferred trigger finishes it at commit: it orders the save, sets the parent, moves main's head, and fills the author, message and agent from the file versions when the writer gave none.
   - **Why:** a writer can't forget (the H21 risk goes away), and raw SQL writes count too. Writers that know better pass a message, kind and author with `saveContext(tx, …)`: change set apply, revert, "Use this version", restore and rename.
   - **What counts:** a file (not a folder) outside `/.system` and not a task file, whose path, current version or presence changed. Locks, sync state and metadata don't count.
   - **Ordering:** a save's place in history is taken at commit, under a per-workspace lock held only for that moment. So two writers touching the same file are always recorded in the order they committed.
2. **Checkpoints** are written by that commit step: the start of history, and then every 100 saves on main.
3. **Browse files at a save** is `GET /saves/:s/files` in H-1. `GET /branches/:b/files?save=` arrives with branches in H-2 and uses the same resolver.
4. **Revert** is a Part G change set (`change_sets.reverts_save_id`), finished and applied in one step. If the files changed since, Part G's merge does the work, and a conflict leaves the change set open to resolve in the Changes view.
5. **Branches need change sets:** turning Branches on also turns change sets on.
6. **Migration 0096**:
   - `branches` (H-1 makes only the main row) and `saves`
   - `save_changes`, which keeps the previous version too, for revert
   - `tree_checkpoints` and `checkpoint_files`
   - `workspaces.branches_enabled`, `change_sets.reverts_save_id`
   - the triggers

## Tasks

1. **0096 and the triggers.** Test (`tests/db/saves.test.ts`): each kind of writer makes one save with the right changes, including raw SQL, a folder rename, a trashed file and an add then delete in one transaction (no save). Workspaces with the setting off record nothing, and parents and checkpoints are right.
2. **Domain `src/lib/domain/saves.ts`:**
   - `enableBranches` and `disableBranches`
   - `listSaves` (filters: path, author, agent; 50 a page)
   - `getSave`, `saveDiff`, `filesAtSave` (checkpoint plus replay, 5,000 a page), `revertSave`
   - `saveContext`
3. **Routes:**
   - `GET /workspaces/:id/saves`
   - `GET /saves/:s`, `/saves/:s/diff`, `/saves/:s/files`, `/saves/:s/zip`
   - `POST /saves/:s/revert`
   - `PUT /workspaces/:id/branches-setting`
   - token rules: `file:read`, `file:write`; the setting is for owners and admins only
   - `/projects` aliases
4. **Writers' messages:** change set apply (title, task, change set), revert, "Use this version" ("Use v1 of login.tsx"), restore ("Restored report.pdf"), rename and move.
5. **App:**
   - a History view in the Files tab (`?view=history`)
   - one save's page (`?save=<id>`) with files, diffs, browse at this save, zip and Revert
   - a "Save" link in the version panel
   - Settings → Branches on and off
   - Browser tests.
6. **CLI:** `nb log [--path] [--author]`, `nb show <save>` and `nb revert <save>`, with `--json` schemas and fake-server tests.

## Close

Benchmark history and replay on a 5,000-file workspace; review and security check; gates; ledger; deploy with the go-ahead (0096); turn Branches on for the user's workspaces; live check.
