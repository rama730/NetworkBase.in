# CLI Phase 1 — Server Layer and Security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One set of server rules for every client: tokens limited to listed routes and their scopes, task status only through the review-aware transition, retried writes deduplicated, abuse limits on every token route, and the resource API the CLI 2.0 and agents build on.

**Architecture:** Keep the existing envelope (`{ success, data, message, errorCode, details }`, `src/app/api/v1/_envelope.ts`) and `DomainError` classes (`src/lib/errors/domain.ts`) — the web app, 1.x CLI and VS Code extension all read them; add codes and an optional `hint`. Token checks live in `requireAuthenticatedUser` (`src/app/api/v1/_shared.ts`), which already resolves every bearer token; the trusted path/method come from the proxy's `x-networkbase-request-target` / `x-networkbase-request-method` headers (`src/proxy.ts:10-12`), which the proxy overwrites on every request. New logic goes in `src/lib/domain/*` and is called by both old `/api/v1/extension/*` routes and the new resource routes.

**Tech Stack:** Next.js 16 route handlers, Drizzle, Postgres 17 (disposable DB via `scripts/db/disposable-db.sh`), Redis (Upstash) for idempotency/rate limits, zod 4.6, `tsx --test`.

**Spec:** `docs/superpowers/specs/2026-11-09-cli-and-agents-report.md` (§28 Area 2, §29 Area 3 A3.6–A3.9/A3.13, A12.3, A12.14, §44), master plan P1.1–P1.14.

## Global Constraints

- Envelope stays `{ success, ... }` (deviation from report A2.6 `{ ok, ... }`, recorded here: changing it would break every existing client; the CLI's own `--json` output uses the report's `{ ok, ... }` envelope in Phase 2).
- Bearer tokens fail closed: a token request whose route isn't listed, or whose trusted target header is missing, gets 403.
- Old `/api/v1/extension/*` routes keep their request/response shapes (1.x CLI and VS Code extension).
- Migrations: next number 0072; applied to the disposable DB only; production on the user's go-ahead.
- DB tests: `DATABASE_URL_FRESH=$(bash scripts/db/disposable-db.sh) npx tsx --test --test-concurrency=1 tests/db/<file>`.

## Review Focus

- A token used on an account/security route (delete, password, MFA, sessions, tokens) → 403 even if the route forgot its own check.
- A PAT made before enforcement (scopes `repo:read`, `repo:write`, `task:write`) keeps working for what it did before.
- `nb push --done` on a review-required task → task goes to review, not done; notifications fire.
- A retried push with the same Idempotency-Key → one version, one receipt.
- Redis down → reads still served; writes still accepted (in-process fallback), not a site-wide outage.
